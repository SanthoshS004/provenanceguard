# ProvenanceGuard Standards Compliance & Mapping Matrix

This document maps ProvenanceGuard architecture, security controls, and verification capabilities to established industry standards.

> [!NOTE]
> **Conformance Claim Policy**: ProvenanceGuard is designed to integrate with and enforce SLSA v1.2, in-toto, Sigstore, SPDX/CycloneDX, and NIST SSDF concepts. ProvenanceGuard does not claim formal third-party certification; compliance statements indicate architectural alignment and verification support.

## 2. Detailed Standards Alignment

### 2.1 SLSA v1.2 Build Provenance Alignment
ProvenanceGuard validates SLSA Level 1–3 provenance attributes:
- **SLSA L1**: Verifies presence of build provenance statement linking output artifact digest to source repository.
- **SLSA L2**: Verifies that provenance is generated by an authenticated build service (hosted CI) with signed attestation envelopes.
- **SLSA L3**: Verifies that the build occurred on an isolated, hardened builder with hermetic build definitions and verified source revisions.

### 2.2 Sigstore Keyless Signing Verification
ProvenanceGuard supports keyless verification via Fulcio (OIDC-issued short-lived x509 certificates) and Rekor (tamper-evident transparency log):
- Extracts subject alternative name (SAN) identities (e.g. `https://github.com/org/repo/.github/workflows/release.yml@refs/heads/main`).
- Verifies certificate validity against Sigstore root of trust (TUFR).
- Cross-references Rekor log inclusion proofs.

### 2.3 SBOM Inventory Comparison
- **SPDX Alignment**: Parses `packages`, `relationships`, and `checksums` arrays.
- **CycloneDX Alignment**: Parses `components`, `dependencies`, and `hashes` arrays.
- **Delta Analysis**: Categorizes inventory changes as `EXACT_MATCH`, `UNEXPECTED_DEPENDENCY`, `MISSING_DEPENDENCY`, or `VERSION_SHIFT`.
